# GHJ Defect Manager

A mobile-first defect management web app — report facility defects with a
photo, let workers fix and close them, and watch completion on a dashboard.
Runs entirely on Firebase (Hosting + Firestore + Anonymous Auth) and installs
on phones as a PWA from Chrome.

**To deploy: see [DEPLOYMENT.md](DEPLOYMENT.md)** (~10 minutes, free plan).

## Features

- **Reporting form** — authorized users (access-code gated) report a defect,
  pick a predefined segment, and attach exactly 1 "before" photo.
- **Worker view** — a list of active defects. Tapping a task moves it to
  *In Progress*; the worker then uploads an "after" photo, types remarks, and
  marks it *Completed*.
- **Dashboard** — Total Defects Reported, Total Defects Completed, and a
  calculated Completion %, auto-refreshing.
- **PWA** — installable from Chrome ("Add to Home screen"), app shell works
  offline, camera opens directly for photo fields on mobile.

## Architecture

- **Firebase Hosting** serves the static app (`public/`).
- **Cloud Firestore** stores the `defects` collection.
- **Anonymous Auth** gives every visitor a session so security rules can
  require authentication without a login screen.
- Photos are compressed client-side (canvas → JPEG, max 1024px) and stored
  as data URLs inside the Firestore document — no Cloud Storage needed,
  which keeps the app on the free Spark plan.
- No build step, no framework: plain HTML/CSS/JS with the Firebase modular
  SDK loaded from CDN.

## Data model (`defects` collection)

| Field              | Type      | Notes                                    |
| ------------------ | --------- | ---------------------------------------- |
| (document ID)      | string    | Auto-generated by Firestore              |
| segment            | string    | Public Area, Rooms, Lobby, Kitchen       |
| status             | string    | Reported → In Progress → Completed       |
| before_picture_url | string    | JPEG data URL, required at creation      |
| after_picture_url  | string    | JPEG data URL, set on completion         |
| remarks            | string    | Set on completion                        |
| created_at         | timestamp | Server timestamp                         |

Status flow and field immutability are enforced by `firestore.rules`.

## Repository layout

```
firebase.json            Hosting + Firestore + emulator config
.firebaserc              Project alias (set yours here)
firestore.rules          Security rules
public/                  The deployed app
  index.html             Home / role picker
  report.html + js       Reporting form (access-code gated)
  worker.html + js       Worker task list & completion flow
  dashboard.html + js    Metrics panel
  js/firebase-config.js  ← paste your Firebase config here
  js/app.js              Shared Firebase init + image compression
  manifest.webmanifest   PWA manifest
  sw.js                  Service worker (app-shell cache)
```

> The original self-hosted version (Express + SQLite) is preserved in git
> history if you ever want to run it on your own server instead.
